# 5 Card Stud for the Emerson Arcadia 2001

A 2650 assembly client for the [5 Card Stud server](https://5card.carr-designs.com/),
running over the FujiNet cartridge mailbox from the Arcadia bring-up at
`fujinet-firmware/pico/arcadia` (protocol v1: everything rides reads, no
banking). Architecture is the Astrocade port's, re-cut for this
hardware: binary `?bin=1` wire format, zero-copy rendering straight out
of the reply window, opaque overdraw per poll, a round/playerCount
watcher instead of dirty rectangles.

## The screen

The game runs a display mode no other client has used: **26-line mode**
(16x26 of 8x8 cells, the lower 13 rows fed from `$1A00`) plus
**multicolor mode** (`$18FD` b7). In multicolor, cell bit 6 picks the
ink and bit 7 the background from two palette registers:

| attr | bits | looks like | used for |
|------|------|-----------|----------|
| `$00` | 00 | black on green | felt text: names, pot, purse |
| `$40` | 01 | red on green | alerts, move clock, chip, F/L markers |
| `$80` | 10 | black on white | black suits, inverse name bar, the menu bar |
| `$C0` | 11 | red on white | red suits, card backs, menu digits |

`$19F8 = $7B` (26-line, ink black, bg green), `$19F9 = $A8` (8x8 cells,
ink red, bg white). The one hazard: a cell of exactly `$C0` -- a *space*
with attrs 11 -- flips the rest of the row into block graphics. The
single glyph writer (`DPUTC` in disp.inc) rewrites that byte to `$80`
(same look, no trap); nothing else stores attributed cells.

The title, name-entry and lobby screens run **13-line doublescan** mode
(8x16 cells, full frame) and use `$1A00-$1ACF` -- free RAM while the
lower screen is off -- as scratch. `GAMEIN` clears it before flipping
26-line on.

Cards are two cells, `[rank][suit]`, both in the suit's attr on the
white body; the ten has its own UDC so it stays one cell; a hidden
`"??"` card is two lattice cells at `$C0` (a red card back); NUL-padded
undealt cards draw felt.

## UDCs and sprites

Eight UDCs at `$1980`, and the first four ARE the sprite images, so the
banks are reloaded per screen (`assets/udc.inc`, generated by
`tools/mkudc.py` from ASCII art):

* **bank T** (title + game): `$38-$3B` hearts/diamonds/clubs/spades
  (= four suit sprites, colored red/red/black/black), `$3C` "10", `$3D`
  chip, `$3E` card-back lattice, `$3F` chevron.
* **bank L** (lobby + name entry): `$38` arrow (= the lobby's white
  cursor sprite), `$39` `/`, `$3A` `-`.

Sprites: the title wave (four suits bobbing under the logo), the lobby
cursor (smooth arrow beside the selected row), the in-game turn cue
(the red heart bobbing at the active seat's marker column, parked when
nobody is up), and the showdown flourish (diamond/club/spade on the
felt row above the result banner). The lobby's "cur / max" slash is the
*built-in* `$01` diagonal -- no UDC spent. DXLAT never emits UDC codes,
so a stray `-` or `:` in a server string can't render as a club.

## Game screen layout (16 x 26)

```
row  0   POT nnnnn   WAIT|RND n|SHOW
rows 2-15  opponent bands, 2 rows each, placed by BANDROW per seat count
rows 17-18 YOUR band (always fixed)
row 20   PURSE nnnnn        move clock (red)
rows 22-24 the white bar: move menu (1 FOLD 2 CHECK ...) on your turn,
           WAITING ON <name> during a live hand, lastResult otherwise
```

A band is name(9) + status marker + chip + bet over hand(5 cards) +
last move. The active player's name renders as an inverse white bar.
Server seat order reads top-down; you are index 0, always the bottom
band.

## Controls

* **disc up/down** -- move (list rows, name wheel)
* **Enter** or **FIRE** -- select / join / accept name
* **keypad 1-5** -- choose a move (validated against the server's menu;
  FIRE shares the '2' wire, so in-game it is strictly "move 2")
* **keypad 0** -- poll now (lobby: refetch)
* **Clear** -- leave the table / back to the name screen / backspace
* **keypad 4 / 6** -- name-entry cursor left/right

## Code layout

Block 1 (CPU `$0000-$0FFF`, page 0) holds everything that touches the
screen; block 2 (CPU `$2000-$2AFF`, page 1) shares its 2650 page with
the mailbox, so the whole network stack lives there and a register arm
or TX append is a direct indexed load -- the inversion of the bring-up's
fujilib, whose remnant here is just the string streamer (its FSTRP
pointer word is page-0 RAM and indirect operands can only be named from
their own page). Page-1 code reaches the few page-0 RAM cells it needs
through DWBE pointer words (mailbox.inc).

net.inc carries the family's five hard-won rules verbatim (CLOSE opens
the *next* request; capture RXLEN immediately after READ; STATUS
settles on two agreeing readings; STATUS byte 3 must be 1; the length
must equal `154 + 33*playerCount`). MCOMMIT derives every sequence
number from the cart's persisted ACKSEQ, which is what
`emu/resettest.lua` proves across a console RESET.

RAM is the whole design constraint: ~84 bytes in 26-line mode (zone A
`$18D0-$18EF`, zone B `$1AD0-$1AFF` -- the ledger is in 5card.asm).
Nothing is buffered: strings render by cursor straight out of the reply
window (`RXNEXT`/`RXPRNT`), numbers print right-to-left into cells
(`NUMPRT`), and the 13-line screens keep their edit buffers in `$1A00`
scratch.

Module budgets (`tools/checksize.py`, run every build): block 1 ~3490
of 4096, block 2 ~1019 of 2816. `checkdepth.py` runs too; note it
under-counts chains through label-dense bodies -- the audited worst
chain is GAMELP > RENDER > SEAT1 > RXPRNT > RXNEXT > MSLICE = 5 of the
2650's 8 RAS entries.

## Build and run

```
./build.sh              # build/5card.bin (8K, FUJI-claimed)
DEMO=1 ./build.sh       # static mock table, no network (art/palette work)
./run.sh                # MAME arcadia + fujinet cart, interactive
make smoke              # headless: join the AI room, ride bot move
                        #   windows with '2', PASS on transaction count
make resettest          # console RESET mid-session; SEQ must continue
```

Environment: `ENDPOINT` (server), `FUJI_FIRMWARE` (tools come from
`pico/arcadia`), `MAME_DIR` (a tree with `emu/apply.sh` applied),
`FUJINET_TCP` (a live fujinet-pc BoIP listener, default
`127.0.0.1:9995`), `FUJINET_DEBUG=1` (log every mailbox transaction --
a `/move` shows as an OPEN with txlen=71 against `/state`'s 69).

## Not here

Astrocade parity: no JSON, no banking, no appkeys/username persistence
(default name ARCADIA, editable per boot), no lastResult scrolling
(three bar rows show the head), no dealing animations -- every poll is
one opaque redraw.
